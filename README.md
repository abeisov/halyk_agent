# Агент проверки кредитных ковенантов

Halyk AI Challenge · команда **First Fin AI**

Агент читает пакет PDF-документов (договоры, аудиторские отчёты, KYC, служебные
записки) и реестр транзакций, и по каждой паре «заёмщик × пункт договора»
определяет: нарушен ли ковенант (`status`), фактическое значение показателя
(`actual`, USD, 2 знака) и транзакцию-улику (`evidence_txn_id`).

## Принцип

> **LLM понимает текст. Код считает числа.**

Ни одно число в `submission.json` не приходит из ответа модели. LLM компилирует
пункт договора в машинную спецификацию (скоуп операций, порог, оговорки,
триггеры, предписания аудита); суммирование, сравнение с порогом и поиск улики —
детерминированный pandas/Decimal.

## Пайплайн

```
master_ledger_2025.csv ─→ ledger.py    реестр -> DataFrame, scenario_id из txn_id,
                                       конвертация в USD до любых агрегаций
documents/*.pdf ────────→ docs.py      атрибуция PDF по ACC-\d+ -> сценарий,
                                       типизация, фильтр недействующих редакций
                          compile.py   [1] вырезка пунктов 6.x из договора (регулярки)
                                       [2] LLM (structured output, t=0): пункт +
                                       леджер + KYC/аудит -> CovenantSpec
                          evaluate.py  actual + status + контрфактическая улика
                          submit.py    заполнение шаблона + валидация
                          run.py       оркестратор: одна команда от папки до JSON
                          score.py     замер по ground_truth (разработка)
```

## Что решено особо

- **Мультивалютность** — таблицы курсов в датасете нет: курс восстанавливается
  из раскрытий в аудите вида «счёт на 57,338.50 EUR урегулирован платежом
  $64,322.63». Курс задан «по курсу фактического расчёта», поэтому он **свой у
  каждого заёмщика** (в приватном наборе — от 1.076 до 1.14): применять общую
  медиану ко всем нельзя. Конвертация до любых агрегаций, `Decimal`, не float.
- **Разная нумерация и язык договоров** — пункты читаются те, что перечислены
  в шаблоне для конкретного сценария (`6.1–6.3`, `6.1–6.4` или `5.1–5.3`), а
  вырезка понимает и «Пункт 6.1», и английское `Section 5.1` в `CREDIT AGREEMENT`.
- **Составная нумерация операций** — `TXN-KC-CAP-29`: `KC` это заёмщик, а `CAP`
  уже категория. Префикс сверяется со списком сценариев из шаблона, иначе
  получился бы несуществующий заёмщик «KC-CAP».
- **«Грязный» реестр** — у части операций пустая сумма; фактические значения
  раскрыты в аудите и служебных записках и применяются как поправки
  (`ledger_amendments`), не правкой исходных данных.
- **Предписания аудита «для целей ковенантов»** — отсечение периода,
  переклассификации, внекнижные обязательства обязательны к применению;
  формулировки «корректировка не требуется» распознаются как ложный след.
- **Carve-outs и триггеры** — `actual` может превышать лимит при статусе
  COMPLIANT; вердикт учитывает оговорки и условия применимости из текста пункта.
- **Улика контрфактически** — единственная транзакция, чьё удаление (или
  включение обратно, для исключённых аудитором) меняет вердикт. Не «самая
  крупная» и не «последняя»: только развернувшая результат. Для коэффициентных
  и агрегатных тестов — `null`.
- **Робастность** — ячейка никогда не остаётся пустой: падение любого этапа
  даёт дефолт, а не пустоту. Вызовы идут через цепочку провайдеров
  (Claude → Gemini → Groq → OpenRouter): исчерпалась квота или деньги — работа
  продолжается на следующем, прогон не встаёт. Кэш спецификаций позволяет
  докомпилировать после обрыва, не пережигая уже сделанные вызовы.
- **Поле `model`** заполняется по факту: каждая спецификация помнит модель,
  которая её выдала, поэтому при переходе по цепочке в сабмит попадает
  реальный список, а не значение из настроек.

## Запуск

```bash
python3 -m venv venv && venv/bin/pip install -r requirements.txt
cp .env.example .env          # вписать GEMINI_API_KEY (aistudio.google.com)

venv/bin/python run.py                                    # data/public -> submission.json
venv/bin/python run.py --input data/private --output submission.json
venv/bin/python run.py --skip-llm                         # пересчёт из кэша спецификаций
```

Датасет кладётся в любую папку с `master_ledger_2025.csv`, `documents/` и
`submission_template.json` (в репозиторий данные не входят). Производные файлы
каждого набора складываются отдельно, в `data/processed/<имя набора>/`.

Ничего не захардкожено: список сценариев читается из шаблона, курсы валют
извлекаются из документов, ни один контрагент или номер транзакции в коде не
упомянут.

## Стек

Python 3.11+ · pandas + Decimal · pymupdf · Gemini (structured output через
pydantic-схему, temperature=0) · без векторных БД и фреймворков — документы
заёмщика помещаются в контекст целиком, 36 ячеек — обычный цикл.
